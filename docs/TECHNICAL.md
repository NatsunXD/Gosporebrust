# Technical notes

## Supported binary identity

- Steam build: `24826606`
- EXE version: `1.8.45317.0`
- `helldivers2.exe` SHA-256: `A09FF52663E73B94FB0CAC0DCB5BA84FFD10ECF44F74A8921AC66AF923988CC3`
- `game.dll` SHA-256: `CC75948D90FDFDE259DCB519E9933DB7FFA3CCB281CE4FB89E6B1B011557470C`

构建器和运行时都会检查这两个哈希。任何一个不一致时都不写入数据。

## Data interpretation

用户提供的对照表确认星球词条定义 ID `1244` 为孢裂。对支持构建进行只读采样后，定义 1244 的已验证结构为：

- kind `40`
- category `13`
- tag hash `0xA3A3DB9F`
- tag hash 表中的索引 `9`

运行时仍会重新查找定义 1244 和它的哈希，而不是盲目采用索引 9。如果定义缺失、形状改变或哈希无法解析，模组进入等待状态且不修改内存。

## Campaign modifier layout

本构建的全局战役修饰表指针位于 `game.dll + 0x2770628`，包含 32 行，每行 356 字节。每行最多五个 16 字节条目；敌人标签条目类型为 17。行的字段为：

- `+80`: 条目数量
- `+84`: 作用域；0 表示星球，2 表示阵营
- `+88`: 作用域值；星球作用域时为星球 ID，阵营作用域时 2 表示终结族
- `+92`: 阵营过滤器；0 表示无额外过滤，2 表示终结族

模组为 173（Gatria）和 268（Luxuriant）分别维护一个 `scope=0` 行，并将过滤器设为终结族（2）。它优先在已有且明确限定目标星球及终结族的未满行中追加标签；如果目标行不存在或已满，则使用完全为空的记录创建新行。它不会向未过滤的星球行追加，以免把孢裂标签扩展到其他阵营。

本版本不写星球可攻打标志、战役操作列表或任务入口。现有证据只覆盖修饰表和任务预览读取路径；没有经过完整 owner、生命周期和回写验证的可攻打状态布局，因此不把这部分作为已实现功能。

## Safety properties

- 写入目标必须完整位于 `MEM_PRIVATE/PAGE_READWRITE` 已提交区域。
- 每个字段写入前重新确认当前表 owner 未变化。
- 写入前比对原字节，写入后回读。
- 中途失败时按相反顺序回滚已经落地的字段。
- 重复更新检测已生效标签，不叠加。
- 不调用原生生成、入队、消费或析构函数。
- 不修改可执行页、队列索引、队列元素、实时人口计数器或反作弊代码。

## Loader resources

归档包含两个互相独立的资源：

- 明文发现入口：`mods/natsun/gosporebrust`
- LuaJIT 实现：`mods/natsun/gosporebrust_impl`

明文入口的第一字节就是 Loader v15 声明。实现资源使用 `1B 4C 4A 02 02` 字节码签名。

## Evidence boundary

只读运行时采样建立了词条、哈希表和战役行布局的证据；现有 `KnowYourConstellation` 解析器明确验证了 `scope=0,value==planet` 的星球匹配条件。合成测试验证了写入、幂等、作用域隔离和回滚。它们不证明游戏最终一定选择孢裂敌人池，也没有证明可攻打状态可以安全解除。精确发布 ZIP 仍需按照 `TESTING.md` 在游戏中验证。
